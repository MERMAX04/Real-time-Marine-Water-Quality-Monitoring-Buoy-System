# 02 — แจ้งเตือนเข้า Telegram เมื่อค่าน้ำวิกฤต (ESP32 ยิงตรง)

เด้งเตือนเข้า **Telegram** มือถือเมื่อค่าน้ำเข้าขั้น **วิกฤต** — ตรงเป้าหมาย "ผ่อนแรงคนเฝ้า"
(ไม่ต้องนั่งจ้อง Dashboard ระบบเตือนเองเมื่อมีปัญหา)

> ✅ **เลือกใช้ Telegram** (ตามที่อาจารย์แนะนำ) — Bot API ฟรี, open, ตั้งค่า 5 นาที ไม่ต้องมี Official Account เหมือน LINE
> โค้ดพร้อมใช้อยู่ใน [`3-supabase-primary/esp32-supabase-4g.ino`](../3-supabase-primary/esp32-supabase-4g.ino) แล้ว — แค่ใส่ token กับ chat id

---

## ตั้งค่า Telegram Bot (ครั้งเดียว ~5 นาที)

### 1) สร้างบอท → ได้ BOT_TOKEN
1. เปิดแอป Telegram ค้นหา **@BotFather** (มีเครื่องหมายถูกฟ้า)
2. พิมพ์ `/newbot` → ตั้งชื่อบอท → ตั้ง username (ต้องลงท้าย `bot`)
3. BotFather จะให้ **token** หน้าตาแบบ `123456789:ABCdefGhIJKlmnOpQ...` → เก็บไว้

### 2) หา CHAT_ID (ปลายทางที่จะส่งหา)
1. **ทักบอทที่เพิ่งสร้าง** ก่อน (กด Start แล้วพิมพ์อะไรก็ได้ เช่น "hi") — สำคัญ! ไม่ทักก่อนจะส่งไม่ได้
2. เปิดเบราว์เซอร์ไปที่ (แทน `<TOKEN>` ด้วย token ของคุณ):
   ```
   https://api.telegram.org/bot<TOKEN>/getUpdates
   ```
3. หาเลข `"chat":{"id":123456789` — เลขนั้นคือ **CHAT_ID** ของคุณ
   > ส่งเข้ากลุ่ม: เพิ่มบอทเข้ากลุ่ม แล้วดู chat id ของกลุ่ม (จะเป็นเลขติดลบ เช่น -100xxxx)

### 3) ใส่ค่าในโค้ด ESP32
ในไฟล์ `esp32-supabase-4g.ino` แก้ 2 บรรทัด:
```cpp
#define TG_TOKEN "123456789:ABCdefGhIJKlmnOpQrS..."   // จาก @BotFather
#define TG_CHAT  "123456789"                           // chat id จาก getUpdates
```

---

## โค้ดทำงานยังไง (อยู่ในสเก็ตช์แล้ว)

หลัง ESP32 ส่งค่าขึ้น Supabase สำเร็จ → เรียก `checkAndAlert()` เช็คเกณฑ์ ถ้าเกินก็ `sendTelegram()`:

- **ส่งข้อความ** = HTTPS POST ไป `https://api.telegram.org/bot<TOKEN>/sendMessage`
  body `{"chat_id":"<CHAT_ID>","text":"..."}` → ตอบ **200** = สำเร็จ
- ใช้ **HTTP application ในตัวโมเด็ม** (AT+HTTP...) เหมือนที่ส่ง Supabase — เสถียรกับ A7670E
  (ต้องเปิด SNI ใน SSL context ไว้ — โค้ดตั้งให้แล้วใน setup)

## เกณฑ์แจ้งเตือน (ปรับได้)
เลือกเฉพาะค่าที่ **"อันตรายจริง"** ไม่ให้เตือนพร่ำเพรื่อ:
| ค่า | เกณฑ์เตือน | เหตุผล |
|-----|-----------|--------|
| DO | < 3 mg/L | ออกซิเจนต่ำ สัตว์น้ำเสี่ยงตาย (ตัวชี้วัดสำคัญสุด) |
| pH | < 7 หรือ > 9 | น้ำกรด/ด่างผิดปกติ |
| อุณหภูมิ | > 33 °C | น้ำร้อน เสี่ยงปะการังฟอกขาว/ออกซิเจนต่ำ |
| ความขุ่น | > 40 NTU | ตะกอน/ปนเปื้อนสูง |

> ⚠️ ไม่ตั้งเกณฑ์กับ **ความเค็ม/Conductivity** เพราะถ้าทดสอบในอากาศ (ค่า=0) จะเตือนรัวๆ — เปิดได้เมื่อทุ่นอยู่ในน้ำจริงตลอด

## กัน "เตือนซ้ำรัวๆ"
โค้ดมี **cooldown 30 นาที/รายการ** อยู่แล้ว (`ALERT_COOLDOWN`) — ค่าวิกฤตที่ส่งทุก 15 วิ จะไม่สแปม
ปรับเวลาได้ที่: `const unsigned long ALERT_COOLDOWN = 30UL*60UL*1000UL;`

---

## ทดสอบว่า Telegram ใช้ได้ก่อน (ไม่ต้องรอค่าวิกฤต)
ลองบังคับส่งครั้งเดียวใน `setup()`:
```cpp
sendTelegram("✅ ทดสอบ: ทุ่น buoy-01 ออนไลน์แล้ว");
```
ได้ข้อความเข้า Telegram = token/chat_id ถูก พร้อมใช้งาน

## ปิดชั่วคราว
ตั้ง `#define TG_ENABLE 0` (เช่น ตอน bench test จะได้ไม่เตือน)

---

## ทางเลือกอื่น (ถ้าไม่ใช้ Telegram)
| ช่องทาง | ข้อดี | ข้อเสีย |
|---------|-------|---------|
| **LINE Messaging API** | คนไทยใช้เยอะ | ต้องมี Official Account + Channel *(LINE Notify ปิดแล้ว มี.ค. 2025)* |
| **อีเมล (SMTP)** | ไม่ต้องลงแอปเพิ่ม | อาจตกไป junk, ช้ากว่า |

## จะให้ Server อาจารย์ (PHP) เป็นคนเตือนแทน ESP32 ก็ได้
ถ้าใช้แผนสำรอง (mode=server): ให้ `4-server-backup/api/save.php` เช็คเกณฑ์ทุกครั้งที่รับค่า แล้ว curl ยิง Telegram เดียวกัน
(ข้อดี: ปรับเกณฑ์ได้โดยไม่ต้อง flash ESP32 ใหม่ / ข้อเสีย: ต้องมี server ออนไลน์)
```php
$msg = "🌊 แจ้งเตือน: DO ต่ำ {$do} mg/L";
file_get_contents("https://api.telegram.org/bot<TOKEN>/sendMessage?chat_id=<CHAT_ID>&text=".urlencode($msg));
```
