# 06 — เอกสารระบบฉบับสมบูรณ์ (สำหรับเล่มปริญญานิพนธ์)

> รวบรวมทุกส่วนของระบบ **ถึงเวอร์ชันล่าสุด** — ใช้คัดลอก/อ้างอิงเข้าเล่มได้โดยตรง
> ระบบทุ่นตรวจวัดคุณภาพน้ำทะเลแบบเรียลไทม์ (Real-time Marine Water Quality Monitoring Surface Buoy System)

---

## 1. ภาพรวมระบบ

ระบบตรวจวัดคุณภาพน้ำทะเลด้วย **ทุ่นลอยน้ำ** ที่วัดค่าคุณภาพน้ำ 7 พารามิเตอร์แบบต่อเนื่อง แล้วส่งขึ้นคลาวด์ผ่านเครือข่าย **4G** เพื่อแสดงผลบน **เว็บแดชบอร์ด** และ **Telegram** พร้อมระบบ **แจ้งเตือนอัตโนมัติ** เมื่อคุณภาพน้ำตกเกณฑ์

**จุดเด่น**
- เลือก **6 โหมดมาตรฐานคุณภาพน้ำทะเลของไทย** ได้ (เกณฑ์/การแจ้งเตือนปรับตามโหมด)
- แสดง **สถานะสีต่อค่า** (🟢 ปลอดภัย / 🟠 ระวัง / 🔴 อันตราย) + **สถานะรวม**
- ตรวจ **ความมีชีวิตของทุ่น** (online/offline) และแยก "sensor เสีย" ออกจาก "ทุ่นหลุด"
- ระบบ **2 สิทธิ์** (admin/user) ควบคุมการเปลี่ยนโหมด

### สถาปัตยกรรมระบบ
```
[ทุ่น: ESP32 + Sensor RS485 + 4G/GPS]
        │  (POST JSON ทุก 15 วิ ผ่าน HTTPS/4G)
        ▼
[Supabase]  ── ตาราง readings / app_settings / tg_subscribers / alert_state
   │   ├── Edge Function: telegram-bot   (ตอบคำสั่งแชท)
   │   ├── Edge Function: telegram-alert (แจ้งเตือนอัตโนมัติเมื่อมีแถวใหม่)
   │   └── Edge Function: admin          (ล็อกอินแอดมิน + เปลี่ยนโหมด verified)
   │
   ├──────────────► [เว็บแดชบอร์ด บน Render]  (realtime + เลือกโหมด + แผนที่)
   └──────────────► [Telegram Bot]           (/status /swim /mode + แจ้งเตือน)
```

> **หลักการออกแบบ:** ทุ่นทำหน้าที่แค่ "อ่าน sensor แล้วส่งค่าดิบ" — ตรรกะการตัดสิน/แสดงผล/แจ้งเตือนทั้งหมดทำ **ฝั่งคลาวด์** (แก้เกณฑ์ได้โดยไม่ต้อง flash ทุ่นใหม่)

## 2. ฮาร์ดแวร์

### 2.1 บอร์ดควบคุมและการสื่อสาร
| ส่วน | รายละเอียด |
|------|-----------|
| ไมโครคอนโทรลเลอร์ | **LilyGO T-Call-A7670 V1.0** (ESP32 + โมดูล 4G **A7670E** + GPS) |
| การสื่อสารข้อมูล | 4G LTE (ส่ง HTTPS ในตัวโมเด็ม — เปิด SNI เพื่อผ่าน Cloudflare ของ Supabase) |
| ระบุตำแหน่ง | GPS ผ่านคำสั่ง AT ของโมเด็ม |

**ขาเชื่อมต่อ (T-Call-A7670 V1.0):**
| อุปกรณ์ | ขา ESP32 |
|---------|----------|
| โมเด็ม TX / RX | GPIO 26 / GPIO 25 |
| โมเด็ม PWRKEY / RST | GPIO 4 / GPIO 27 |
| RS485 (sensor) RX / TX | GPIO 32 / GPIO 33 |
| RS485 DE/RE | -1 (โมดูล TTL485-V2.0 คุมทิศอัตโนมัติ) |

### 2.2 เซนเซอร์คุณภาพน้ำ (Online Multi-parameter Sensor)
สื่อสารแบบ **Modbus RTU** (RS485, 9600 8N1, address 0x01) — เป็นตัวเครื่องแบบหลายหัววัด (multi-probe) ที่**เลือกติดตั้งหัววัดได้** ชุดที่ใช้ติดตั้ง **4 โพรบ** ให้ **7 ค่าวัด**:

| # | โพรบ | รุ่น | หลักการ | ค่าที่ได้ |
|---|------|------|---------|-----------|
| 1 | DO | Y504-B | Fluorescence | ออกซิเจนละลายน้ำ + % อิ่มตัว |
| 2 | TUR | Y510-C | 90° Scattered light | ความขุ่น |
| 3 | CT/SAL | Y521-B | Four-electrode | การนำไฟฟ้า + ความเค็ม + อุณหภูมิ |
| 4 | pH | Y532-B | Glass electrode | ความเป็นกรด-ด่าง |

**หัววัดเสริมที่รองรับแต่ไม่ได้ติดตั้ง:** ORP (Y533-B) · คลอโรฟิลล์ CHL (Y515-B) · น้ำมัน OIW (Y616-C) · สาหร่าย BGA (Y613-C)
— ข้อมูลจริง 597 แถวอ่านได้ 0.000 ทุกแถว (ORP ในน้ำทะเลจริงต้องได้หลักร้อย mV) จึงตัดออกจากระบบ · รายละเอียด [`09-probe-plan-A-B.md`](09-probe-plan-A-B.md)

**ไฟเลี้ยงเซนเซอร์:** DC 12–24V (USB จ่ายไม่พอ ต้องมี adapter แยก) · ต่อ **GND ร่วม** กับ RS485

> ⚠️ **TDS ไม่ใช่โพรบ** — เดิมเคยแสดง แต่ตัดออกเพราะเป็นค่า **คำนวณจาก EC** (≈ EC × 0.65) ซ้ำกับความเค็ม/การนำไฟฟ้า

## 3. ซอฟต์แวร์ฝั่งทุ่น (Firmware — `esp32-supabase-4g.ino` / `Full-Version.ino`)

### 3.1 วงรอบการทำงาน
1. ทุก **15 วินาที** อ่านค่า sensor → สร้าง JSON → POST ขึ้น Supabase (`/rest/v1/readings`)
2. อ่านพิกัด GPS (ถ้าล็อกดาวได้) แนบไปด้วย
3. ถ้าอ่าน sensor ไม่สำเร็จ → ส่ง **heartbeat** (`sensor_ok=false`) เพื่อบอกว่า ESP+4G ยังทำงาน

### 3.2 Register map ของเซนเซอร์ (Modbus)
**อ่านรวดเดียว** — register `0x2600`, 22 registers = 11 ช่อง float (little-endian) · firmware **ใช้ 7 ค่า** (ช่องที่ไม่ได้ติดโพรบไม่ใช้):

| ลำดับ | ค่า | | ลำดับ | ค่า |
|-------|-----|--|-------|-----|
| 1 | DO (mg/L) ✅ | | 7 | คลอโรฟิลล์ — ไม่ใช้ |
| 2 | ความขุ่น (NTU) ✅ | | 8 | OIW/BGA — ไม่ใช้ |
| 3 | การนำไฟฟ้า (mS/cm) ✅ | | 9 | ความเค็ม (ppt) ✅ |
| 4 | pH ✅ | | 10 | TDS (คำนวณ) — ส่งแต่ไม่แสดง |
| 5 | อุณหภูมิ (°C) ✅ | | 11 | DO (%) ✅ |
| 6 | ORP — ไม่ใช้ | | | |

> ⭐ ถ้าเฟรมผ่าน CRC แต่ pH, DO และ EC เป็น 0 ทั้งหมด (sensor ยังไม่พร้อม/ไฟไม่พอ) firmware ถือว่า**อ่านไม่สำเร็จ** และส่ง heartbeat `sensor_ok=false` แทนการส่งค่า 0
> (ถ้าติดหัววัดเสริมในอนาคต: OIW/BGA ใช้ช่อง 8 ร่วมกัน อ่านแยกได้ที่ `0x260D` / `0x260E`)

### 3.3 การส่งข้อมูล
- ส่งเป็น JSON ผ่าน **HTTPS ในตัวโมเด็ม A7670** (เปิด SSL context + SNI → แก้ปัญหา error 715 กับ Supabase ที่อยู่หลัง Cloudflare)
- โหมดทดสอบ `USE_FAKE=1` = ส่งค่าปลอมครบทุกค่าที่ใช้ (ทดสอบ 4G โดยไม่ต้องต่อ sensor) · production ตั้ง `USE_FAKE=0`

## 4. ฐานข้อมูลและคลาวด์ (Supabase)

### 4.1 ตารางหลัก
| ตาราง | หน้าที่ |
|-------|---------|
| `readings` | ค่าที่ทุ่นส่ง (do_val, do_pct, temp, ph, sal, cond, turb, sensor_ok, lat, lon, created_at) · คอลัมน์ chl/orp/oil/algae เป็นคอลัมน์สำรองสำหรับหัววัดเสริม (ยังไม่ใช้) |
| `app_settings` | โหมดที่เลือกอยู่ (key='mode') — ใช้ร่วมทั้งเว็บ/Telegram |
| `tg_subscribers` | chat_id ผู้รับแจ้งเตือน (กด /start) |
| `alert_state` | เวลาแจ้งเตือนล่าสุด (กันเตือนซ้ำ = cooldown 30 นาที) |

### 4.2 Edge Functions (Deno/TypeScript)
| Function | หน้าที่ |
|----------|---------|
| `telegram-bot` | รับคำสั่งแชท (/status /swim /mode /start /stop /help) |
| `telegram-alert` | ทริกเกอร์เมื่อมีแถวใหม่ → ถ้าสถานะรวม "แดง" ตามโหมด → แจ้งเตือนทุก subscriber |
| `admin` | ล็อกอินแอดมิน (เว็บ) + เปลี่ยนโหมดแบบ verified token |

**Config กลาง `water-modes.json`** = แหล่งเกณฑ์ 6 โหมด (แก้ที่เดียวใช้ร่วมทั้ง Edge/เว็บ/PHP) · ตรรกะประเมินอยู่ที่ `water-eval.ts`

## 5. ระบบ 6 โหมดมาตรฐานคุณภาพน้ำทะเลของไทย

อ้างอิง **ประกาศคณะกรรมการสิ่งแวดล้อมแห่งชาติ (มาตรฐานคุณภาพน้ำทะเล)** แบ่งเป็น 6 ประเภทตามการใช้ประโยชน์:

| ประเภท | โหมด | หัวข้อที่แสดง |
|--------|------|--------------|
| 1 | อนุรักษ์ทรัพยากรธรรมชาติ | 🌱 คุณภาพน้ำเชิงนิเวศ |
| 2 | อนุรักษ์แหล่งปะการัง | 🪸 สถานะน้ำต่อแหล่งปะการัง |
| 3 | เพาะเลี้ยงสัตว์น้ำ | 🐟 น้ำเพื่อการเพาะเลี้ยง |
| 4 | นันทนาการ (ว่าย/เล่นน้ำ) — ค่าเริ่มต้น | 🏖️ สถานะการลงเล่นน้ำ |
| 5 | อุตสาหกรรมและท่าเรือ | 🏭 น้ำเขตอุตสาหกรรม/ท่าเรือ |
| 6 | เขตชุมชนชายฝั่ง | 🏘️ น้ำเขตชุมชนชายฝั่ง |

### 5.1 เกณฑ์ที่ต่างกันตามโหมด (🟢 เขียว / 🟠 ส้ม)
| โหมด | DO (mg/L) | อุณหภูมิ (°C) | ความขุ่น (NTU) |
|------|-----------|--------------|----------------|
| 1 อนุรักษ์ | ≥5 / ≥4 | ≤32 / ≤33 | ≤15 / ≤30 |
| 2 ปะการัง | **≥7 / ≥6** | **≤31 / ≤32** | **≤10 / ≤20** |
| 3 เพาะเลี้ยง | ≥5 / ≥4 | ≤32 / ≤33 | ≤15 / ≤40 |
| 4 นันทนาการ | ≥5 / ≥4 | ≤33 / ≤34 | ≤15 / ≤40 |
| 5 อุตสาหกรรม | ≥5 / ≥4 | ≤32 / ≤33 | ≤15 / ≤40 |
| 6 ชุมชน | ≥5 / ≥4 | ≤32 / ≤33 | ≤15 / ≤40 |

### 5.2 เกณฑ์ที่เหมือนกันทุกโหมด
| ค่า | 🟢 เขียว | 🟠 ส้ม |
|-----|---------|--------|
| pH | 7.0 – 8.5 | 6.5 – 9.0 |
| ความเค็ม | 29 – 35 ppt | 26 – 37 |
| การนำไฟฟ้า (EC) | 35 – 53 mS/cm | 30 – 58 |

> อุณหภูมิ/ความเค็มใช้ **ค่าสัมบูรณ์** (แปลงจากเกณฑ์กฎหมาย "เปลี่ยนจากธรรมชาติ" โดยสมมติน้ำทะเลไทย ~31 °C)

### 5.3 การประเมินสถานะ (โมเดล A)
**สีต่อค่า:** ค่าอยู่ในช่วง green → 🟢 · ไม่เขียวแต่อยู่ในช่วง orange → 🟠 · นอกช่วง → 🔴

**สถานะรวม:** แต่ละค่ามีระดับ **วิกฤต (critical)** หรือ **เฝ้าระวัง (advisory)** ต่อโหมด
```
มีค่า "วิกฤต" ค่าใดแดง   → 🔴 รวมแดง (ไม่ควรใช้น้ำ/ทำกิจกรรม)
ไม่มี แต่มีค่าใดแดง/ส้ม   → 🟠 รวมส้ม (ระวัง)
ทุกค่าเขียว              → 🟢 รวมเขียว
```

**ระดับความสำคัญต่อโหมด** (🛡️ วิกฤต · 😌 เฝ้าระวัง):
| โหมด | pH | DO | อุณหภูมิ | เค็ม | EC | ขุ่น |
|------|----|----|---------|------|-----|-----|
| 1 อนุรักษ์ | 🛡️ | 🛡️ | 🛡️ | 😌 | 😌 | 😌 |
| 2 ปะการัง | 🛡️ | 🛡️ | 🛡️ | 😌 | 😌 | 🛡️ |
| 3 เพาะเลี้ยง | 🛡️ | 🛡️ | 🛡️ | 😌 | 😌 | 😌 |
| 4 นันทนาการ | 🛡️ | 🛡️ | 😌 | 😌 | 😌 | 😌 |
| 5 อุตสาหกรรม | 🛡️ | 😌 | 😌 | 😌 | 😌 | 😌 |
| 6 ชุมชน | 🛡️ | 🛡️ | 😌 | 😌 | 😌 | 😌 |

> ตัวอย่าง: **DO 3.5 mg/L** → โหมดนันทนาการ = 🔴 รวมแดง (DO วิกฤต) · โหมดอุตสาหกรรม = 🟠 รวมส้ม (DO เฝ้าระวัง)

### 5.4 ค่าที่ไม่ได้ประเมิน
ORP, คลอโรฟิลล์, น้ำมัน และสาหร่าย ไม่ได้ติดตั้งหัววัด จึงไม่มีเกณฑ์และไม่แสดงในระบบ (ดูข้อ 2.2)

## 6. เว็บแดชบอร์ด (Dashboard บน Render)

- **การ์ด 7 พารามิเตอร์** (5 ค่าหลักจาก 4 โพรบ + DO%/อุณหภูมิ เป็นค่ารอง) — แต่ละการ์ดมี badge สีตามโหมด
- **แถบเลือกโหมด** (6 ประเภท) — เห็นเฉพาะแอดมิน
- **แถบสถานะรวม** — เปลี่ยนหัวข้อ/ข้อความ/สี ตามโหมด + เหตุผล
- **ดัชนีคุณภาพน้ำ (WQI)** ถ่วงน้ำหนัก + **พยากรณ์แนวโน้ม** (Holt smoothing) + จับผิดปกติ (z-score)
- **สถานะทุ่น (liveness):** 🟢 ออนไลน์ (<45 วิ) / 🟠 ค้าง (45 วิ–5 นาที) / 🔴 ออฟไลน์ (>5 นาที)
- **แผนที่ Google Map** ฝังตามพิกัด GPS จริง (ถ้าไม่มีพิกัด → แจ้ง "ยังไม่พบพิกัด GPS")
- **Export CSV** ติ๊กเลือกค่าที่ต้องการได้
- แหล่งข้อมูล: Supabase realtime (สลับ mock/server ได้ที่ `CONFIG.mode`)

## 7. Telegram Bot + แจ้งเตือน

| คำสั่ง | หน้าที่ |
|--------|---------|
| `/status` | ค่าน้ำล่าสุดทุกค่า (แยกสี 🟢🟠🔴) + สถานะทุ่น + สถานะรวมตามโหมด |
| `/swim` | สถานะรวม "ทำกิจกรรมได้ไหม" ตามโหมด |
| `/mode` | ดู/เปลี่ยนโหมด (เปลี่ยนได้เฉพาะแอดมิน — chat_id ใน env) |
| `/start` `/stop` | สมัคร/ยกเลิกรับแจ้งเตือน |
| `/help` | เมนู |

**แจ้งเตือนอัตโนมัติ:** เมื่อมีแถวใหม่ใน readings และสถานะรวม "แดง" ตามโหมด → ส่งหาผู้สมัครทุกคน (cooldown 30 นาที/ชุดค่าที่ตก)

## 8. ระบบสิทธิ์ 2 บทบาท (Role) + ความปลอดภัย

| | **user** (ค่าเริ่มต้น) | **admin** |
|--|------------------------|-----------|
| ค่าน้ำ/สถานะ/แผนที่ | ✅ เห็น | ✅ เห็น |
| แถบเลือกโหมด | ❌ ซ่อน | ✅ เห็น + เปลี่ยนได้ |
| เปลี่ยนโหมดผ่าน API | ❌ ล็อก (RLS) | ✅ ผ่าน Edge Function |

**การเข้าใช้ admin:** เข้า URL `/…/admin` → modal ล็อกอิน → ถูกต้อง → เห็นแถบโหมด + ปุ่ม logout

**ความปลอดภัย (server-side จริง):**
- รหัสผ่านเก็บใน **Supabase secret** (`ADMIN_USER`, `ADMIN_PASS`) — ไม่อยู่ในโค้ด
- Edge Function `admin` ตรวจรหัส → คืน token (SHA-256 ของรหัส) ให้เว็บเก็บใน sessionStorage
- การเปลี่ยนโหมดต้องแนบ token → function verify ก่อนเขียน (service_role)
- **RLS** ตัดสิทธิ์ anon `update` บน app_settings → user ยิง API เปลี่ยนโหมดตรงไม่ได้

## 9. สรุปพารามิเตอร์ 7 ค่า (ตารางอ้างอิง)

| # | พารามิเตอร์ | หน่วย | โพรบ | วัด/คำนวณ | มีเกณฑ์ตัดสินโหมด |
|---|------------|-------|------|-----------|------------------|
| 1 | ออกซิเจนละลายน้ำ (DO) | mg/L | Y504-B | วัด | ✅ (วิกฤต) |
| 2 | ออกซิเจนอิ่มตัว (DO%) | % | Y504-B | วัด | ✅ (เฝ้าระวัง) |
| 3 | อุณหภูมิ | °C | Y521-B | วัด | ✅ |
