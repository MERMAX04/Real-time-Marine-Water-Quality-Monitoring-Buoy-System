# 09 — แผนจัดการโพรบเสริม 4 ตัว (OIW / ORP / CHL / BGA)

> ✅ **สถานะ (2026-10-08): ดำเนินการแผน A แล้ว** — ตัด 4 ค่าออกจาก firmware / เว็บ / Telegram / PHP / config (commit `d49d6a9`)
> firmware compile ผ่าน · ตรรกะเว็บ, Edge Function, PHP ทดสอบด้วยข้อมูลจริงให้ผลตรงกัน · ระบบเหลือ 7 ค่า
> แผน B (`probe_check.py`) เก็บไว้ใช้ยืนยันกับเซนเซอร์จริงเพื่อใส่ภาคผนวก

**ปัญหา:** ค่า น้ำมัน (OIW), ORP, คลอโรฟิลล์ (CHL), สาหร่าย (BGA) อ่านได้ **0.00 ตลอด** จากเซนเซอร์จริง
(ค่าที่ไม่เป็น 0 ในฐานข้อมูลมีแค่แถว mock วันที่ 28 ก.ย. — chl 2.5 / orp 300 / oil 0.5 / algae 8000)

**ที่ตรวจแล้ว:** firmware อ่านตำแหน่งถูกต้องตามคู่มือทุกตัว (ORP=f[5], CHL=f[6], OIW=0x260D, BGA=0x260E)
เซนเซอร์เป็นตัวเครื่องแบบ multi-probe ที่ **เลือกติดโพรบเองได้ทั้ง 8 ตัว** (คู่มือหน้า 7 "Optional sensors" รวม DO/TUR/CT/pH ด้วย)
ชุดที่ใช้ติดตั้ง 4 โพรบ: **DO** (ให้ DO + DO%) · **TUR** · **CT/SAL** (ให้ EC + ความเค็ม) · **pH** — ส่วน ORP/CHL/OIW/BGA ไม่พบข้อมูลจริง
**หลักฐานจากข้อมูลจริง:** 597 แถวที่เซนเซอร์ทำงาน ทั้ง 4 ค่า = 0.000 ทุกแถว · ORP = 0.000 ในน้ำทะเลจริง (เป็นไปไม่ได้ถ้ามีโพรบ) → **สันนิษฐานว่าไม่ได้ติดตั้งโพรบ** (ยืนยันขั้นสุดท้ายด้วยแผน B)

**ลำดับ:** ทำ **แผน B ก่อน** (ยืนยันด้วยการอ่าน register จริง) → ถ้ายืนยันว่าอ่านไม่ได้ → ใช้ **แผน A** (ตัดออก)

## แผน B — ตรวจสอบว่าอ่าน register ได้จริงไหม

### สิ่งที่ต้องเตรียม
- เซนเซอร์ + ไฟ 12V (≥1A) + **GND ร่วม**
- สาย **USB-to-RS485** ต่อ PC (พอร์ตเดิม COM9) — *ถอด RS485 ออกจาก ESP32 ก่อน* (ห้ามมี master 2 ตัวบนสายเดียว)
- จุ่มหัวโพรบในน้ำ (น้ำทะเล/น้ำในถัง) — ORP, pH ต้องจุ่มน้ำถึงจะอ่านค่าสมเหตุสมผล

### ขั้นตอน
| ขั้น | ทำอะไร | คำสั่ง |
|---|---|---|
| 1 | ดูด้วยตาที่ตัวเซนเซอร์ — นับหัวโพรบที่ติดจริงเทียบรุ่นในคู่มือ (ORP Y533-B · OIW Y616-C · CHL Y515-B · BGA Y613-C) ช่องที่ไม่มีโพรบมักเป็นฝาปิด | — |
| 2 | รันสคริปต์ตรวจอัตโนมัติ (อ่าน status + เวอร์ชัน + เฟรมรวม + register แยก 5 รอบ แล้วสรุปผลรายโพรบ) | `py probe_check.py COM9 5` |
| 3 | ถ้าต้องการเจาะทีละคำสั่ง ใช้คอนโซลเดิม | `py rs485_console.py COM9` แล้วพิมพ์ `status` `orp` `chl` `oil` `algae` `all` |
| 4 | **ทดสอบกระตุ้นโพรบ** (กรณีอ่านได้แต่ค่านิ่ง/ใกล้ 0) — ดูว่าค่าขยับไหม ดูตารางด้านล่าง | `py probe_check.py COM9 10` ระหว่างกระตุ้น |
| 5 | แคปหน้าจอผลสรุปเก็บไว้ (ใส่ภาคผนวกเล่มได้) | — |

### คำสั่ง Modbus ดิบ (กรณีใช้โปรแกรมอื่น เช่น Modbus Poll)
| อ่าน | คำสั่ง (เติม CRC แล้ว) |
|---|---|
| Sensor status 0x0800 | `01 03 08 00 00 02 C6 6B` |
| ORP 0x260B | `rs485_console.py` → `orp` (เติม CRC ให้อัตโนมัติ) |
| CHL 0x260C / OIW 0x260D / BGA 0x260E | `chl` / `oil` / `algae` |

### การกระตุ้นโพรบ (แยก "ไม่มีโพรบ" ออกจาก "น้ำสะอาดจริงเลยได้ ~0")
| โพรบ | ปกติในน้ำทะเล | วิธีทดสอบ |
|---|---|---|
| **ORP** | +100 ~ +400 mV (**ไม่มีทางเป็น 0.000 เป๊ะ**) | จุ่มน้ำธรรมดา → ต้องได้ค่าบวกหลักร้อย · ถ้า 0.000 ตลอด = ไม่มีโพรบแน่นอน |
| **CHL** | 0.x–ไม่กี่ µg/L | เอาใบไม้สีเขียว/น้ำที่มีตะไคร่ จ่อหัวโพรบ → ค่าต้องเพิ่ม |
| **BGA** | 0–หลักพัน cells/mL | น้ำจากบ่อ/ตู้ปลาที่มีตะไคร่เขียว → ค่าต้องเพิ่ม |
| **OIW** | ~0 ppm | หยดน้ำมัน (เช่นน้ำมันพืช/ดีเซล 1-2 หยด) ในแก้วน้ำ จุ่มโพรบ → ค่าต้องเพิ่ม |

### อ่านผลอย่างไร (ผลจาก `probe_check.py`)
| ผลที่ได้ | ความหมาย | ทำต่อ |
|---|---|---|
| ✅ อ่านได้ + ค่าขยับเมื่อกระตุ้น | โพรบมีและทำงาน | **ไม่ต้องทำแผน A** สำหรับตัวนั้น · ตรวจว่า firmware ส่งค่าขึ้นได้ (อาจต้องรอ warm-up/คาลิเบรต) |
| ⛔ ได้ `0.000` เป๊ะทุกรอบ (ไบต์ `00 00 00 00`) แม้กระตุ้นแล้ว | ไม่มีโพรบ/โพรบไม่ทำงาน | ใช้ **แผน A** ตัดตัวนั้นออก |
| ❌ EXCEPTION | sensor ไม่รองรับ register นั้น | ใช้ **แผน A** |
| ⚠️ ไม่ตอบ | ปัญหาสาย/ไฟ/GND | แก้การต่อแล้วรันใหม่ (ไม่ใช่ปัญหาโพรบ) |
| status 0x0800 bit ของโพรบนั้น = 0 | sensor รายงานเองว่าไม่ได้เสียบ/สื่อสารผิดปกติ | ยืนยันผลข้างบน → แผน A |
| status = 1 (เสียบอยู่) แต่ค่า = 0 และ **K = 0** ที่ 0x1100 | โพรบมี แต่ค่าคาลิเบรตถูกตั้งเป็น 0 | ตั้ง K/B ใหม่ (ค่าโรงงานมักเป็น K=1, B=0) แล้วอ่านใหม่ |
| status = 1 แต่ค่า = 0, K ≠ 0 | โพรบมีแต่ยังไม่ตอบ (warm-up / สกปรก / ไม่ได้จุ่มน้ำ) | ทำขั้นกระตุ้นโพรบ |

### ความหมาย Sensor Status 0x0800 (จากคู่มือ — 2 registers = 4 ไบต์)
| ไบต์ | ความหมาย | bit |
|---|---|---|
| 00 | Error flag (0 ปกติ / 1 ผิดปกติ) | bit0 แปรงทำความสะอาด · bit1 ไฟเลี้ยง · bit2 โพรบผิดปกติ/เสียบไม่สุด |
| 01 | Power supply flag (0 ผิดปกติ / 1 ปกติ) | bit0–5 ไฟเลี้ยงสาย 1–6 |
| 02–03 | **Probe flag (1 = เสียบอยู่ สื่อสารปกติ / 0 = ไม่ได้เสียบ)** | bit0 DO · bit1 Conductivity · bit2 Turbidity · **bit3 CHL** · bit4 pH · **bit5 OIW/BGA** · bit6–7 สงวน · **bit8 ORP** · bit9 Salinity |

> OIW กับ BGA มี bit เดียวร่วมกัน (bit5) — ใช้ช่องโพรบเดียวกัน ติดได้ทีละตัว
> `probe_check.py` เลือกลำดับไบต์ของ word นี้ให้อัตโนมัติ โดยยึดว่าโพรบพื้นฐานที่ใช้งานได้จริง (DO/EC/ขุ่น/pH/เค็ม) ต้องเป็น 1

### ค่าคาลิเบรต K/B (0x1100 + offset, 4 registers = K + B เป็น float DCBA)
offset: 01 DO · 02 Turbidity · 03 CT · 04 pH · **05 ORP** · **06 CHL** · **07 OIW/BGA** · 08 Salinity
ค่าที่อ่านได้ = K × ค่าดิบ + B → **ถ้า K = 0 จะได้ 0 ตลอด** `probe_check.py` อ่าน K/B ของ ORP/CHL/OIW ให้แล้ว

> หมายเหตุ: OIW กับ BGA ใช้ช่อง f[7] ร่วมกันในเฟรมรวม — ถ้าติดโพรบตัวใดตัวหนึ่ง f[7] จะแสดงค่าของตัวนั้น
